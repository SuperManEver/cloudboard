# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

CloudBoard is a learning-oriented, production-structured SaaS app for managing personal projects and tasks. The main goal is hands-on experience with AWS: Amplify Gen 2, Cognito, DynamoDB, Lambda, API Gateway, and CDK. It is built in phases, and each phase is scoped tightly. Don't implement features from later phases (see README "Roadmap"). Avoid adding dependencies, state-management frameworks or abstractions that the current phase doesn't need. For UI, use shadcn/ui (see below) instead of other UI libraries or hand-rolled equivalents.

Stack: Node 24 (`.nvmrc`; `engines` is `>=24 <25`), npm, Next.js 15 App Router, React 19, TypeScript strict, Tailwind CSS 4 (CSS-first config in `src/app/globals.css`, no `tailwind.config`), shadcn/ui (Radix base, `nova` preset, Lucide icons; config in `components.json`), ESLint 9 flat config, Prettier 3 (default options; `eslint-config-prettier` disables conflicting ESLint rules), Amplify Gen 2.

## Commands

Run `nvm use` first. The machine's nvm default is Node 20, so commands fail or behave differently without it.

```bash
npm run dev         # Next.js dev server
npm run build       # production build (also runs lint + type check)
npm run lint        # eslint
npm run format      # prettier --write . (format:check for CI-style check)
npm run typecheck   # tsc --noEmit
npx ampx sandbox --profile default     # deploy per-developer cloud sandbox and watch amplify/
npx ampx sandbox delete --profile default
```

There is no test suite yet.

## Architecture

- **Two TypeScript projects in one package.** `amplify/` is the Amplify Gen 2 backend (CDK-based). It has its own `tsconfig.json` (ES2022, `$amplify/*` → `.amplify/generated/*`) and a `package.json` that only sets `"type": "module"`. The root `tsconfig.json` includes `**/*.ts`, so `npm run typecheck`, `npm run build` and `npm run lint` all check `amplify/` too. A backend type error breaks the frontend build.
- **Backend entry point is `amplify/backend.ts`.** Each resource lives in `amplify/<category>/resource.ts` and only deploys once it is registered in `defineBackend({...})`. CDK-level overrides (e.g. `backend.auth.resources.cfnResources...`) also go in `backend.ts`.
- **Current backend state (Phase 2):**
  - `auth` supports email/password and Google federation (`amplify/auth/resource.ts`). The Google client ID and secret are the Amplify secrets `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`; a deploy fails if they're missing. OAuth callback and logout URLs are listed per origin in `resource.ts`, so a new origin (another branch domain, a custom domain) must be added there. Identity-pool guest (unauthenticated) identities are explicitly disabled in `backend.ts`.
  - `amplify/data/resource.ts` is a placeholder. The generated sample `Todo` model with `allow.guest()` was removed on purpose.
  - `a.schema({})` doesn't type-check (Amplify needs at least one model), so `data` is **not** registered in `backend.ts`. When adding the first model, restore `defineData` and register `data`. Use owner-based authorization and never `allow.guest()`/public rules.
- **`amplify_outputs.json`** is generated by `ampx sandbox` (locally) or `ampx pipeline-deploy` (Amplify Hosting builds) and git-ignored. `src/lib/amplify-client.ts` and `src/lib/amplify-server.ts` import it, so `npm run build` and `npm run typecheck` need it to exist.
- **Auth flow:** client components import `@/lib/amplify-client` for its side effect (configures Amplify with `ssr: true`, so tokens live in cookies). Server code reads the session through `@/lib/amplify-server`. `src/middleware.ts` protects `/dashboard` and sends signed-in users away from `/sign-in` and `/sign-up`. Google sign-in returns to `/oauth/callback`.
- **Frontend layout (`src/`):**
  - `app/` holds App Router routes.
  - `components/ui/` holds reusable, feature-agnostic UI: shadcn components (add with `npx shadcn@latest add <name>`, don't hand-write equivalents) plus a few custom ones like `logo.tsx`. Prefer shadcn's color tokens (`bg-background`, `text-muted-foreground`, `bg-primary`, `border`) over raw Tailwind palette colors. The brand color is `--primary` (sky) in `globals.css`.
  - Dark mode follows the OS (`prefers-color-scheme`). `globals.css` replaces shadcn's class-based `.dark` variant with a media-query variant, so there's no theme toggle.
  - `next.config.ts` lists `radix-ui` in `optimizePackageImports`. Without it, a single Radix client component (e.g. `Separator`) adds ~90 kB to the page bundle.
  - `features/` holds feature modules (auth, projects, tasks).
  - `lib/` holds non-UI code. Amplify client configuration (with `@aws-amplify/adapter-nextjs` for server-side use) belongs here, never in components.
  - `types/` holds shared types.
- **Component defaults:** Server Components by default. Add `"use client"` only when a component needs interactivity or browser APIs.

## AWS constraints

- The sandbox is not an emulator. `ampx sandbox` creates real, billable resources. Get explicit user approval and verify the account and region (`aws sts get-caller-identity`) before running anything that creates or changes AWS resources. Never delete a sandbox without approval.
- Deploy with the `default` profile: a non-root IAM user signed in via `aws login` (short-lived console credentials), region us-east-1. Never use the root account, never create access keys, and don't create additional IAM users. If credentials have expired, ask the user to run `aws login --profile default`.
- The user's shell may set `AWS_PROFILE` to a read-only org profile that can't deploy. Always pass `--profile default` explicitly.
- OAuth client secrets go in `npx ampx sandbox secret set <NAME> --profile default` for the sandbox and in Amplify console → Hosting → Secrets for deployed branches, never in the repo.

## Known dependency notes

- `npm audit` reports a PostCSS advisory via `next`. The only fix is Next 16, which is outside the required 15.x, so don't run `npm audit fix --force`. The other advisories come from dev-only Amplify CLI dependencies.
- npm 11 skips install scripts for `esbuild` and `unrs-resolver` until they are approved (`npm install-scripts approve <pkg>`). Everything works without them.
